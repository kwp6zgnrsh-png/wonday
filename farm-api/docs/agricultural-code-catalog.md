# 작목·공통 작업 코드 기준

사용자와 합의한 기준 목록을 JAR에 포함한다. 실행 환경에서 Downloads 폴더나 Excel 설치, 외부 API 호출은 필요하지 않다. 이번 범위는 APP-01 조회의 코드 이름 표시이며 등록 허용값 검증이나 기존 값의 일괄 변환은 포함하지 않는다.

| 리소스 | 원본 파일·위치 | 처리 |
| --- | --- | --- |
| `reference/crop-codes.json` | `농산물소득정보OpenAPI_제공코드.xlsx`, `jakmokCode` 시트, B열 코드·C열 이름 | 249행 중 동일 코드·이름 중복 7건을 합쳐 242개 코드 |
| `reference/work-type-codes.json` | `농작업+표준코드_공통.xlsx`, `농작업 표준코드_공통` 시트, B열 코드·A열 이름 | 표시 형식 `0000`에 맞춰 75개 코드를 4자리 문자열로 보존 |

분석한 원본의 SHA-256:

- 작목: `10d831d7ba54d4971929a1edce9543e6ff2e48ac00955c91b531cfc8fd603c32`
- 공통 작업: `9690b9d0b2a9ec535e0300d805e37859d816df4b0298209e8b943cf923355cf5`

예시:

```json
{
  "cropCode": "VC02100100100102",
  "cropName": "노지가을배추",
  "workTypeCode": "0058",
  "workTypeName": "수확"
}
```

코드는 숫자로 변환하거나 임의로 재발급하지 않는다. 작목 코드는 길이가 모두 같지 않으며 원문 그대로 보관한다. 기준 목록에 없는 기존 코드도 응답에서 유지하고 이름만 `null`로 반환한다. 품목별 작업 연결은 후속 범위이므로 특정 작목과 작업의 조합을 이번에 제한하지 않는다.

이 파일은 제공된 자료를 기준으로 하며 외부 서비스의 최신 목록을 자동 동기화하지 않는다. 보험 서버와 프론트에서도 같은 코드·이름 목록을 공유해야 한다. 과거 확정 약정의 코드를 새 코드로 덮어쓰지 않는다.
