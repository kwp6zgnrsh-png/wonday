# 고용주의 개인별 근무 완료 API

## 요청과 응답

`POST /api/work-assignments/{assignmentId}/completion`

농업 고용주 로그인 세션(`FARMSESSION`)과 로그인 후 새로 조회한 CSRF 토큰을 사용한다. 요청 본문은 필요 없다. 고용주 ID·근로자 ID·완료 시각을 클라이언트에서 받지 않는다. 보험 서버 전용 Bearer 토큰은 이 API의 로그인·CSRF를 대신하지 않는다.

성공과 같은 근무에 대한 재요청은 모두 `200 OK`이며, 다음 두 필드만 반환한다.

```json
{
  "assignmentId": 501,
  "completedAt": "2026-11-27T18:10:00+09:00"
}
```

## 처리 기준

- DB에서 고용주 역할을 다시 확인하고, 본인 공고에 연결된 개인별 확정 근무만 처리한다.
- 현재 공고나 일정이 아닌 확정 근무의 `agreedEndAt`·`agreedTimeZone`으로 종료 여부를 판단한다. 서버 현재 시각이 약정 종료 시각과 같거나 이후이면 완료할 수 있다.
- 취소·조기 종료 기록이 있으면 완료하지 않는다.
- 최초 완료 요청을 처리한 서버 시각을 UTC·마이크로초로 저장하고, 응답은 약정 시간대의 오프셋으로 표현한다. 기존 합의인 `GMT+9` 약정은 `+09:00`으로 반환한다.
- 재요청 시 최초 완료 시각과 최초 처리자를 유지한다. 완료 취소·정정 API는 제공하지 않는다.
- 완료는 급여 지급이나 이체 완료를 의미하지 않는다. 약정·지원·공고·일정 조건은 변경하지 않는다.
- 완료된 근무에 취소·조기 종료를 새로 기록하거나 기존 변경 사유를 정정할 수 없다.
- `work_change`와 보험 변경 목록에는 완료 이벤트를 추가하지 않는다.

## 실패 응답

```json
{
  "code": "WORK_NOT_FINISHED",
  "message": "약정 근무 종료 시각 이후에 완료할 수 있습니다."
}
```

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | INVALID_REQUEST | 양수가 아닌 ID 또는 ID 변환 오류 |
| 401 | 기존 인증 응답 | 로그인 세션 없음 |
| 403 | EMPLOYER_ROLE_REQUIRED | 근로자 요청 또는 DB에서 고용주 역할이 확인되지 않음 |
| 403 | 기존 CSRF 응답 | CSRF 누락·오류 |
| 404 | WORK_ASSIGNMENT_NOT_FOUND | 근무 없음 또는 다른 고용주 소유 |
| 409 | WORK_NOT_FINISHED | 약정 종료 시각 전 |
| 409 | WORK_ALREADY_CANCELLED | 개인별 취소 기록 있음 |
| 409 | WORK_ALREADY_EARLY_ENDED | 개인별 조기 종료 기록 있음 |
| 503 | SERVICE_UNAVAILABLE | 필수 종료 시각·시간대 해석 불가, DB 장애·잠금 시간 초과 등 |
| 500 | INTERNAL_SERVER_ERROR | 기타 내부 오류 |

완료 이후 취소·조기 종료 저장 경계는 `409 WORK_ALREADY_COMPLETED`를 반환한다. 이는 후속 CHANGE 사용자 API에서도 유지해야 하는 저장 규칙이다.

## 저장과 동시 요청

신규 V11은 `work_assignment.completed_at_utc`와 `completed_by`만 추가한다. 두 컬럼은 모두 NULL이거나 모두 값이 있어야 하며, 처리자는 회원 FK로 보관한다. 기존 행은 두 값 모두 NULL로 남긴다. 종료 시각이 지났다는 이유로 기존 행을 완료로 보완하지 않는다.

완료 서비스는 READ_COMMITTED 트랜잭션에서 확정 근무 행을 먼저 비관적 쓰기 잠금으로 읽고, 변경 행을 확인한다. 기존 취소·조기 종료 기록 및 사유 보완도 근로자 발행 스트림 잠금 뒤 같은 확정 근무 행 → 변경 행 순서로 접근한다. 따라서 완료가 잠금을 보유한 동안 취소 기록이 끼어들지 않도록 구성했다. 실제 MySQL 경합과 롤백은 아직 실행 검증하지 않았다.

## 보험 상세와 farm-demo

보험용 확정 근무 상세와 같은 조회 서비스를 쓰는 demo 상세에 `completedAt` 필드를 추가했다.

- 완료된 근무: 최초 저장한 완료 시각을 약정 시간대의 오프셋으로 반환.
- 미완료 및 기존 행: `null`.
- `completedBy`는 응답하지 않는다.
- 기존 필수 약정 정보가 누락된 행은 기존대로 503이며, 누락 값을 추측해서 채우지 않는다.

기존 `/demo/job-location` 화면에서 근로자로 로그인한 후 본인 약정을 선택해 상세를 조회하면 좌표와 `completedAt`을 함께 확인할 수 있다. 보험 토큰을 화면에 노출하지 않는다.

고용주는 새 `/demo/work-completion` 화면에서 본인 공고의 최근 확정 근무 100건을 조회하고, 근로자·약정 ID를 선택해 완료할 수 있다. 로그인 화면에는 고용주용 링크를 추가했다. 화면·조회용 컨트롤러·서비스·저장소는 `farm-demo`에서만 활성화한다.

| 메서드 | 경로 | 처리 |
| --- | --- | --- |
| GET | `/demo/work-completion` | 간이 화면 |
| GET | `/demo/api/employer/work-assignments` | 세션 고용주 본인 공고의 최근 확정 근무 목록 |
| GET | `/demo/api/employer/work-assignments/{assignmentId}` | 본인 공고의 약정 종료 시각·변경 상태·저장된 completedAt |
| POST | `/api/work-assignments/{assignmentId}/completion` | 기존 완료 API 그대로 호출 |

화면만 익명으로 열 수 있으며, 조회 API는 고용주 세션과 DB 역할 재확인이 필요하다. 타인 근무의 상세는 404다. 완료 버튼은 새 CSRF 토큰을 받아 실제 완료 API를 호출한다. 토큰은 표시·저장·요청 기록에 포함하지 않는다. POST 응답을 화면에서 완료로 간주해 채우지 않고 별도 상세 GET으로 저장값을 재조회해 비교한다.

### 화면 확인 순서

1. Docker MySQL이 준비된 상태에서 기존 `farm-demo` 실행 설정으로 서버를 재시작한다. 서버 시작 시 신규 V11이 적용돼야 한다.
2. `/demo/login`에서 고용주로 로그인하고 **개인별 근무 완료 · 완료 일시 확인** 링크를 연다.
3. 목록에서 본인 공고의 확정 근무를 선택한다. 상세의 약정 종료 시각과 `completedAt: null`을 확인한다.
4. 종료 시각이 지난 근무의 **완료 처리**를 누른다. 실제 POST 200 → 상세 GET 200과 두 응답의 완료 시각 일치를 확인한다.
5. 같은 근무의 **완료 재요청**을 누르면 최초 완료 시각이 유지되는지 비교한다.
6. 종료 전 근무, 취소 또는 조기 종료된 근무도 선택해 서버의 실제 409 코드·메시지를 확인한다.
7. 근로자로 계정을 바꾸면 고용주용 조회는 거부된다. 근로자 본인 약정은 기존 좌표 demo에서 조회할 수 있다.

연결이 끊겨 저장 여부를 알 수 없거나 409 등 오류가 나면 자동 재요청하지 않는다. 상세를 다시 조회한 뒤 진행한다. 공고명은 현재 공고의 목록 식별용 표시이며, 종료 가능 여부와 완료 시각의 기준은 확정 근무에 저장된 약정이다.

완료 처리 자체는 Apidog에서 고용주로 로그인 → 로그인 후 CSRF 재조회 → 본인 공고의 확정 근무 ID로 본문 없는 POST 순서로 확인할 수 있다. 선정·확정 API는 아직 후속 범위이므로 현재 DB에 실제 확정 근무 행이 있어야 한다. 데모가 확인용 근무를 자동 생성하지 않는다.

보험 담당자에게 상세 응답에 `completedAt: null | 오프셋 포함 일시`가 추가됐음을 공유한다. 이후 구현할 개인별 근무 내역에도 같은 저장값을 사용한다.

## 이번 작업의 확인 범위

테스트 실행·DB 적용·서버 기동·실제 HTTP 검증·커밋·푸시는 하지 않는다. 기존 테스트는 응답 DTO 생성자, 변경 저장 잠금 메서드, V11 적용 개수·버전 기대값과 컬럼 확인만 맞췄다. 신규 동작의 자동 검증과 기존 테스트 실행 결과는 별도로 확인해야 한다.
### 사용자 수동 확인 기록 (2026-11-27)

사용자가 farm-demo에서 완료 요청 200, 상세 재조회의 완료 시각 반영, 같은 근무 재요청 시 최초 완료 시각 유지를 확인했다. 화면의 항목명과 안내는 한국어인 '완료 일시'로 표시하고, API JSON 필드명은 기존 completedAt을 유지한다. 이는 사용자 보고에 따른 수동 확인 기록이며 자동 테스트나 동시성·트랜잭션 통합 검증 결과는 아니다.
