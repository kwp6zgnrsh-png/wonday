로그인을 확인합니다.

고용주와 근로자는 각각 실제 로그인 계정으로 처리합니다. 처음에는 demo-employer·demo-worker 계정을 사용하는 것이 가장 간단합니다. 같은 브라우저에서는 로그인 계정을 바꾸면 이전 계정 세션도 바뀝니다. 두 역할을 동시에 보려면 일반 창과 시크릿 창을 나누세요. 선정·재확인은 실제 API를 호출하며 서버의 권한·CSRF·버전 검사를 통과해야 합니다.

시연 준비 전입니다.

1. 시연 데이터 준비와 사례 선택

처음 준비는 201, 같은 고용주·근로자·날짜의 재사용은 200입니다. 재요청으로 기존 상태를 초기화하지 않습니다. 고용주로 준비하면 상대는 demo-worker, 근로자로 준비하면 상대는 demo-employer입니다. 기존 회원의 이름·비밀번호는 변경하지 않습니다.

조건 버전은 조회 응답에서 자동으로 가져옵니다. 쓰기 요청 직전에 새 버전을 몰래 덮어쓰지 않습니다. 다른 창에서 조건을 바꿨다면 기존 화면의 요청은 409가 될 수 있습니다. 최신 조건을 직접 조회한 뒤 다시 요청하세요.

3. 고용주 — 선정·재요청·409

「정상 선정」 사례: 선정 201 → 같은 요청 200, 확정 근무 ID·확정 일시가 유지되는지 확인하세요.

「변경 조건 재확인 후 선정」 사례: 근로자가 확인하기 전에는 409입니다. 근로자 계정에서 재확인한 뒤 다시 선정하면 201입니다.

이전 버전 버튼은 버전이 2 이상인 사례에서 조회 버전보다 1 작은 값을 의도적으로 전송합니다. 정원 충족·마감·모집 취소·시작 경과·취소된 근무는 해당 사례에서 일반 선정 버튼으로 409를 확인하세요. 이미 확정된 정상 요청은 이전 버전을 보내도 기존 결과를 200으로 반환합니다. 버전 409는 아직 선정하지 않은 사례에서 확인하세요.

3. 근로자 — 재확인·재요청·409

「변경 조건 재확인 후 선정」 사례에서 변경 내용을 먼저 읽고 재확인을 누르세요. 200 응답 후 같은 요청을 보내도 최초 재확인 ID·시각이 유지돼야 합니다.

최초 지원 버전이 최신이면 별도 재확인 기록 없이 200입니다. 재확인은 선정이나 자리 확보가 아닙니다. 고용주가 이미 선정했다면 재확인 대상이 아니므로 409입니다.
