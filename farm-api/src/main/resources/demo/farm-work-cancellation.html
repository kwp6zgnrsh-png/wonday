로그인 상태를 확인합니다.

고용주 계정으로 시연 데이터를 준비하고 확정 근무 한 명을 취소합니다. 시연 데이터도 DB에 저장되며 서버 재시작·다시 준비로 취소 상태를 초기화하지 않습니다. 처음에는 demo-employer 계정 사용을 권장합니다. 시연 준비에는 demo-worker 계정도 필요합니다.

로그인 확인 후 시연 데이터를 준비해 주세요.

1. 시연 데이터 준비 · 사례 선택

준비 전입니다. 위 버튼 한 번으로 취소 가능한 확정 근무와 거절 사례를 준비합니다.

준비 201은 새 공고 생성, 준비 200은 기존 공고 재사용입니다. 취소 API의 성공 상태코드는 최초·재요청 모두 200입니다. 기존 WORK-02 시연 공고를 재사용하므로 선정 화면에서도 이번에 준비한 확정 상태가 보일 수 있습니다.

3. 최초 취소 · 재요청 · 다른 사유 충돌

  1. 정상 확정 사례를 선택하고 「취소 요청 보내기」를 누르면 최초 취소 200을 확인할 수 있습니다.
  2. 「같은 내용으로 재요청 · 200 확인」을 누르면 직전 성공 요청을 그대로 보냅니다. 아래에서 변경 ID·버전·시각이 유지되는지 확인하세요.
  3. 「다른 사유로 재요청 · 409 확인」을 누르면 직전 성공 요청의 사유만 바꿔 보냅니다. 기존 취소 기록은 유지되어야 합니다.

재요청 버튼은 이 화면에서 취소 200을 한 번 받은 후 활성화됩니다. 입력 칸을 수정해도 재요청 버튼은 직전 성공 요청을 기준으로 동작합니다. 이미 취소된 사례는 첫 클릭부터 기존 결과 200을 반환합니다. 통신 오류 때 자동 재전송하지 않습니다.
