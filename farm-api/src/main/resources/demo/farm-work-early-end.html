개인별 조기 종료 확인

로그인 상태를 확인합니다.

고용주 계정으로 시연 데이터를 준비하고 확정 근무 한 명의 실제 종료 시각과 사유를 기록합니다. 시연 데이터도 DB에 저장되며 서버 재시작·다시 준비로 조기 종료 상태를 초기화하지 않습니다. 처음에는 demo-employer 계정 사용을 권장합니다. 시연 준비에는 demo-worker 계정도 필요합니다.

로그인 확인 후 시연 데이터를 준비해 주세요.

1. 시연 데이터 준비 · 사례 선택

준비 전입니다. 위 버튼 한 번으로 조기 종료 가능한 확정 근무와 거절 사례를 준비합니다.

준비 201은 새 공고 생성, 준비 200은 기존 공고 재사용입니다. 조기 종료 API의 성공 상태코드는 최초·재요청 모두 200입니다. CHANGE-03 전용 가상 공고를 준비하며, 같은 날 다시 준비해도 기존 조기 종료 기록을 초기화하지 않습니다.

2. 선택한 근무 · 조기 종료 사유

위 사례 표의 「이 사례 선택」을 눌러 주세요.

저장 상태 조회 전

최초 입력은 약정 종료 후 24시간까지입니다. 기한이 지나도 정상 완료로 자동 변경하지 않습니다. 기한 초과 사례는 위 표의 「입력 기한 초과 409·문의 안내」 행에서 선택한 뒤 기록을 보내세요.

달력·시간을 바꾸면 전송 시각을 GMT+9의 +09:00 형식으로 갱신합니다. 기본 시각은 서버가 제공한 소수초를 그대로 보관합니다. 허용 범위와 현재 시각 검사는 서버가 합니다.

앞뒤 공백 제거 후 0 / 500 코드 포인트

빈 설명은 서버에서 null로 저장합니다. 500자를 초과하거나 기상 세부 사유를 비워도 요청은 보낼 수 있어 서버의 400 응답을 확인할 수 있습니다.

3. 최초 조기 종료 · 재요청 · 다른 사유 충돌

  1. 정상 확정 사례를 선택해 실제 종료 시각을 확인한 뒤 「조기 종료 기록 보내기」를 누르면 최초 기록 200을 확인할 수 있습니다.
  2. 「같은 내용으로 재요청 · 200 확인」을 누르면 직전 성공 요청을 그대로 보냅니다. 아래에서 변경 ID·버전·시각이 유지되는지 확인하세요.
  3. 「다른 사유로 재요청 · 409 확인」 또는 「종료 시각 변경 · 409 확인」으로 직전 성공 요청과 다른 내용을 보냅니다. 기존 조기 종료 기록은 유지되어야 합니다.

재요청 버튼은 이 화면에서 조기 종료 200을 한 번 받은 후 활성화됩니다. 시각·사유 입력 칸을 수정해도 재요청 버튼은 직전 성공 요청을 기준으로 동작합니다. 종료 시각 변경 버튼은 직전 성공한 실제 종료 시각보다 1초 뒤로 전송합니다. 이미 조기 종료된 사례는 첫 클릭부터 기존 결과 200을 반환합니다. 통신 오류 때 자동 재전송하지 않습니다.
